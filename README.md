# tinymd

一个安静的 Markdown 工作空间。基于 **Electron 44** + **Tiptap 3**（含官方 `@tiptap/markdown`）构建，遵循苹果设计语言：大量留白、细腻的字排、克制的色彩。

![技术栈](assets/image20260924201526303.svg) ![tiptap](assets/image20260924201526349.svg)

## 功能

- **打开方式**：启动即欢迎页，可「打开文件夹」进入工作空间，也可直接打开单个 Markdown —— **打开文件等于把它的父目录当成工作空间**（不再有「单文件模式」这个第三种形态）。两者都进「最近打开」列表（最多记 5 条、默认露 2 条，其余在列表内滚动，不会把上方内容顶出窗口）。
- **文档目录树**：左侧递归展示当前文件夹内的文件夹与 Markdown 文件，自动监听磁盘变化并刷新。
- **文件树懒加载**：目录默认全部闭合，只有展开时才读那一层（主进程每次只读一层，目录节点不带 children）。好处：打开一个几万文件的仓库不再需要把整棵树读进内存；代价：展开每个目录多一次读盘（读完后会记住，折叠再展开不重复读）。过滤规则：只显示 `.md` 系文件与目录，点开头的条目和 `.git` / `node_modules` 这类一律不出现。
- **打开单个文件不选中**：用「打开文件…」/ 拖拽 / 双击进来的，树里**不会**高亮那一篇 —— 树此时可能是整个闭合的（打开动作不替你展开），凭空多一个高亮反而让人以为已经展开了。从文件树里点开的仍然会高亮（那是「树跟着正文走」）。
- **重复打开是无操作**：再打开一次当前正开着的那个文件夹，或用「打开文件…」选中的正是当前编辑的那一篇，都原地不动 —— 不重载文件树、不动当前文档、不切形态。选同一个文件夹早先会把正在编辑的那一篇**清空**（重新 setRoot 之后走 `showEditorEmpty()`），用「打开文件…」选当前那篇会把目录模式的窗口**硬拽成单文件模式**、文件树整个消失。判重用 `samePath()`（util 里）：统一分隔符、去尾斜杠、Windows/macOS 忽略大小写，所以「同一个文件夹的不同写法」也认得出。要切换就直接点文件树里的另一篇。
- **一个文件只有一个窗口**：同一个 Markdown 不会同时开在两个窗口里 —— 两个窗口各存一份内存副本、各自自动保存，写回去就互相覆盖，而且界面上看不出来。已经打开过的文件再点「在新窗口中打开」不会再开一个，而是把已有的那个窗口切到前面（右键菜单里这一项会显示成「前往已打开的窗口」；就是当前这篇则灰显并标注「已在此窗口」）。在文件树里点到它、或从最近打开 / 拖拽 / 双击 / 命令行进来也是同一套判定：不切换当前文档、不换模式，只在状态栏说明一声。**不是**锁文件 —— 改完关掉窗口，或关掉工作空间，其它窗口就能接手。
- **整屏两栏：左栏 + 正文**。文档目录（大纲）是**左侧栏的一页**，与文件树同栏、**互斥显示**（同一时刻只有一页可见），点标签或按 `Ctrl/Cmd + Shift + O` 来回切。整屏因此没有第三栏，正文不被夹在中间。
  - **头部是四枚纯图标按钮**（30px / 圆角 7 / 图标 16px，与顶栏 `.topbar-right` 完全同款）：左端两枚切页、右端两个新建。「文件 / 大纲」**没有文字标签**，当前页靠 `.icon-btn.active` 的 accent 底色表示 —— 同一行里混一套带字分段控件和一套图标按钮会像两种东西。切页按钮组本身**不带底色/边框**（会与active 底色打架），分组感只靠 4px 的 gap。
  - **互斥由一个枚举保证**：状态是 `sidePane: 'files' | 'outline'`（持久化在 `localStorage` 的 `jianmo.sidebarPane`），不是两个独立布尔 —— 早先的 `tocOpen` + `no-sidebar` 能组合出「文件树和大纲同时开着」的非法态，单枚举从根上不存在这种可能。
  - **两页各自的滚动位置分别记忆**：文件树滚到一半切到大纲、切回来还在原处。
  - **切页不改变窗口与正文尺寸**：侧栏宽度与目录开合彻底解耦，`PANELS_EXCLUSIVE_W`(800) 那套「窄窗口下两块互斥」的判据随之删除 —— 压根没有第二块面板。
  - **大纲没有标题时标签置灰**，并在 `title` 里写明原因（纯文本模式 / 这篇没标题）。文档没标题时点它只给一句状态栏提示，不会切过去；已经在大纲页时标题被删光会自动退回文件页。
  - `Esc` **不再**收走大纲 —— 它是侧栏的一页而不是浮层，想切回文件页点标签或用快捷键。
- **底部状态栏是整窗一条**：左端是工作空间路径、中间是保存状态 / 临时提示、右端是字数，三段同处一条基线。（早先底部有两条同高却左右各断一半的底栏 —— 侧栏自己一条、编辑区一条，路径与字数不在一条线上，扫一眼是「两截」。）
  - 正文左右留白固定 **20px**、两边一样宽（不再有窄 / 中 / 宽三档）。⚠️ 20 是实测出来的下界：右边最外 10px 是滚动条槽，留白低于 20 时正文离滚动条不足 10px，末行的 `==高亮==`、行内代码底色就快贴上去了（16px 实测已经明显发紧）。滚动条占掉右边一条，正文右侧内边距里把它扣掉，屏幕上的左右留白才真的一样宽。
  - 路径是长路径时从**左侧**截断（`direction: rtl`）—— 保留盘符与开头，比从右侧截断更认得出是哪个文件夹；完整路径在 `title` 里。
- **可拖拽边栏**：侧栏右缘可拖动调整宽度（180–520px）并自动记忆。窗口不动，拖动直接改变编辑区宽度 —— 上限永远停在「正文还剩 480px」那条线上，不会把正文挤没；窗口被拖窄导致空间不够时也会被夹回来，但夹的只是**这一次渲染出来的宽度**，你拖出来的偏好值不受影响，空间回来就还给你。
- **正文占满内容区，左右留白恒定最小**：不管窗口多大，正文两侧各留 20px（`--content-pad`），文档吃掉全部剩余空间。窗口越宽正文越宽，不设上限。纯文本模式用同一套（同样没有 `max-width`），切换模式时首行位置不动。
  - **曾经试过定宽中轴（`max-width: 38em` + 居中），已撤销**。理由：中轴必然在两侧各留一大片空白（1080 宽时左右各约 250px，1600 宽时各约 500px），那一大片既不是文档内容、也不是控件位置，纯粹是空的 —— 视觉上比「字排得宽」更抢眼。**留白恒定最小、文档吃掉剩下的**更符合「编辑器」的身份。
  - 代价要说清楚：行宽不再有天花板，1600 宽的窗口下正文可到 1200+px（约 75 字/行）。中文舒适行宽是 30–40 字，超出后眼睛从行尾回到行首容易漏行。**想压行宽只能靠限制窗口宽度，不是限制正文。**
  - ⚠️ 滚动条槽在 `padding` 之外，所以左右天然对称，不需要再「扣滚动条凑对称」——`--sb-w` 这个 CSS 变量已随之删除（JS 侧的 `scrollbarWidth` 仍留着，只给 `sidebarMaxWidth` 算侧栏上限时扣用）。
- **顶栏右侧是「打开文件夹 / 打开文件 / 纯文本模式 / 设置」**：前两个与欢迎页那对按钮走同一个 `chooseFolder` / `chooseFile` 入口，工作空间开着时也能直接换一个文件夹、或直接开一个散落在别处的单文件（点了会切到单文件模式，侧栏只剩大纲那一页）。原先这一排最左边是「文档目录」—— 目录并进侧栏之后它没有意义了，位置换成了这两个。
- **主题切换**：在设置中心选择「暗色（中性）」或「亮色」并自动记忆，默认使用中性主题。设置是应用级的，多窗口同时打开时会即时同步。
- **所见即所得编辑**：Tiptap v3，支持标题、列表、任务列表、引用、代码块（含语言）、表格、图片、链接、高亮；输入 `# `、`- `、`> ` 等 Markdown 前缀自动转换格式，输入 `==文字==` 自动转为高亮。
- **纯文本模式**：可在顶栏切换到 Markdown 源文本编辑；切回所见即所得模式时，以当前纯文本重新加载整篇文档，避免两种视图状态不一致。
- **斜杠命令菜单**：在空行或词首输入 `/` 呼出插入菜单，支持标题、列表、任务、引用、代码块、表格、分割线、图片；继续输入可按名称 / 拼音缩写过滤（如 `/bg` → 表格），`↑↓` 选择、`Enter` 确认、`Esc` 关闭。代码块内不触发。
- **Markdown 双向转换**：使用官方 `@tiptap/markdown`（marked 内核）解析与序列化，保存时最大限度保留源文件语法（如 ```` ```js ```` 语言标记、`==高亮==`）。
- **自动保存**：停止输入约 0.6s 后自动写盘，`Ctrl/Cmd+S` 可立即保存；窗口关闭前兜底同步保存。
- **图片原样本地存储**：粘贴 / 拖入 / 按钮插入图片时，原始二进制直接写入本地；Markdown 或富文本中的网络图片也会自动下载并替换为本地相对路径，不转 base64。可在图片设置中选择存储目录并调整网络图片大小上限（默认 30 MB）。
- **拖拽 / 右键打开 md**：把 `.md` 拖到窗口任意位置即可打开（欢迎页整页都是拖放区，仅顶部 38px 留给拖窗）；在资源管理器中右键 / 双击 Markdown 用「tinymd」打开，会以单文件模式载入该文件（开发模式可传参模拟，打包版依赖 `fileAssociations` 注册）。

## 开发

```bash
npm install        # 安装依赖（若 electron 二进制未下载：cd node_modules/electron && node install.js）
npm run dev        # Vite 开发服务器 + Electron（带 HMR）
```

## 打包

```bash
npm run dist:win   # Windows NSIS 安装包（x64）
npm run dist:mac   # macOS dmg（需在 macOS 上执行）
npm run dist       # 按 electron-builder.yml 默认平台打包
```

产物输出到 `release/`：`tinymd-<版本>-setup.exe`（NSIS 安装包）、`tinymd-<版本>-<架构>.dmg`（macOS 磁盘映像），以及 `win-unpacked/` 免安装版。

已配置 `.md` / `.markdown` 的 `fileAssociations`，打包安装后可在资源管理器双击 / 右键用「tinymd」打开。

> 上面三条命令已内置国内镜像（`ELECTRON_MIRROR` / `ELECTRON_BUILDER_BINARIES_MIRROR`）。
> 镜像刻意写在 npm 脚本而不是 `electron-builder.yml` 里：`@electron/get` 读取镜像的顺序是「环境变量 > 配置文件」，写进配置文件会连 CI 也一起走国内源，而 GitHub 的 runner 在海外。

## 发布

推一个 tag 就会自动出 Windows + macOS 安装包并创建 Release：

```bash
# 1. 改版本号：package.json 与 package-lock.json 里的根级和 packages[""]，共 3 处
#    （只改 package.json 会让 CI 的 npm ci 报版本不一致）
# 2. 提交后打 tag 并推送
git tag v0.2.1 && git push github v0.2.1
```

> 只想验证打包改动、不想发 Release？推一个**名字里带 `-` 的预发布 tag**（如 `v0.2.2-rc.1`），
> 按工作流里的条件它只构建、不发布。

产出的 Release 附件：

| 平台 | 附件 |
| --- | --- |
| Windows | `tinymd-<版本>-setup.exe`（NSIS 安装包）、`tinymd-<版本>-win-unpacked-x64.zip`（免安装版）、`latest.yml` |
| macOS | `tinymd-<版本>-universal.dmg`（一个 dmg 同时含 arm64 与 x64） |

工作流（`.github/workflows/release.yml`）分三个 job：`windows-latest` 与 `macos-latest` 各自打包并上传 artifact，最后一个 `publish` job 汇总两边的产物、用 `gh release` 统一创建 Release（不并发生成，也不会被两个平台互相覆盖）。macOS 那个 job 在打包后会跑一次签名自检（`codesign --verify --deep --strict`），确保 ad-hoc 签名确实生效且结构完好。

需要重跑时，在 Actions 页面对该 run 点 **Re-run all jobs**；用 **Run workflow** 手动触发时，选 tag 会发布、选分支只构建（发布步骤带 `--verify-tag`，tag 不存在会直接报错而不是静默发错版本）。

> 构建步骤里 `--publish never` 不能省。electron-builder 在 CI 环境下检测到 tag 会把发布模式隐式切成 `onTag`，再依据 `package.json` 的 `repository` 字段推断出 GitHub provider，接着因为拿不到 `GH_TOKEN` / `GITHUB_TOKEN` 而报错 —— 表面现象是「打包步骤莫名其妙失败」。发布统一交给 `gh release`，所以显式关掉它的自动发布。

### 前置检查

- 仓库 **Settings → Actions → General → Workflow permissions** 需要是 **Read and write permissions**，否则 `gh release` 会因 `GITHUB_TOKEN` 只读而 403（工作流里已声明 `permissions: contents: write`，但仓库设置为只读时无法提权）。
- CI 里不跑 `npm run build:icon`：`build/icon.png`、`build/icon.ico` 已提交入库，且与 `icon-candidate-25.*` 内容一致，直接在打包时复用。改图标后记得本地重跑 `npm run build:icon 25` 再提交。

## macOS 用户必读：首次打开会被拦截

**macOS 包带 ad-hoc 签名，但没有 Apple 开发者证书、未公证**。仓库里没有证书，CI 通过
`mac.identity: "-"` 显式启用 ad-hoc 签名（不写这行的话 electron-builder 找不到证书会直接跳过签名，
产物反而更差 —— 详见下面「想彻底去掉这个提示」）。

ad-hoc 签名是本地生成的、不需要任何账号的签名，作用有两个：让 App 的签名结构合法
（Apple Silicon 上未签名的二进制根本不允许运行），以及证明包在签完之后没被改动过。
但它**不包含开发者身份**，所以 Gatekeeper 依然会拦下它：

> 未打开「tinymd」 — Apple 无法验证「tinymd」是否包含可能危害 Mac 安全或泄漏隐私的恶意软件。

（不同 macOS 版本的文案略有差异，也可能显示为「已损坏」——那只是 Gatekeeper 的措辞，
不是文件真的坏了。）

**这是预期行为，不是包损坏。** 两种放行方式，任选其一：

### 方式 A：系统设置（Apple 官方途径，推荐）

1. 从这个对话框点 **「完成」** —— 不要点「移到废纸篓」。
2. 打开 **系统设置 → 隐私与安全性**，向下滚动到「**安全性**」区域。
3. 会看到一条「已阻止使用「tinymd」，因为来自身份不明的开发者」，点它旁边的 **「仍要打开」**。
4. 弹窗里再点一次 **「打开」**，然后输入密码 / Touch ID 确认。

批准一次即可，之后双击就能正常打开（系统会把它记为例外）。

> **找不到「仍要打开」按钮？** 该按钮**只在被拦下后的约一小时内出现**，且界面上没有任何倒计时提示
> （[Apple 官方说明](https://support.apple.com/zh-cn/guide/mac-help/mh40616/mac)：「此按钮在你尝试打开该 App 后一小时内可用」）。
> 按钮消失了就再双击一次 App 让它被拦下，然后立刻回到「隐私与安全性」。
> 另外先确认「允许从以下位置下载的 App」不是 **App Store**（选「App Store 和被认可的开发者」）。

更新到新版本后，新下载的 App 会被重新打上隔离标记，可能还需要再放行一次。

### 方式 B：终端清掉隔离标记（更快）

先把 App 从 dmg 拖进「应用程序」，然后执行：

```bash
xattr -cr /Applications/tinymd.app
```

### 两个常见误区

- ⚠️ **不要再按老教程「右键 → 打开」**。Apple 已在 macOS 15 (Sequoia) 起**移除**了 Control-click 覆盖 Gatekeeper 的能力
  （[Apple 官方说明](https://developer.apple.com/news/?id=saqachfa)），只能用方式 A 或 B。
- `sudo spctl --master-disable` 那套「允许任何来源」的老办法，在新版 macOS 上已被新的 Gatekeeper 工具堵掉，同样不可用。

### 关于签名的三个档位

| 签名方式 | 费用 | 用户看到什么 |
|---|---|---|
| 不做签名（找不到证书时 electron-builder 的默认行为） | — | 最差：签名结构缺失，对话框可能只剩「移到废纸篓」 |
| **ad-hoc 签名**（当前采用） | **免费** | 仍被拦一次，按上面方式 A / B 放行 |
| Developer ID 签名 + Apple 公证 | **$99/年** | 双击直接打开，零警告 |

只有第三档能真正消掉提示：需要 Apple Developer Program 账号（个人也能注册，但证书上会挂真实姓名），
用 Developer ID 证书签名后提交 Apple 公证（notarize）。这是独立的一套流程，目前未配置。

顺带一提，免费签名的替代渠道基本都已关闭 —— OSSign 的申请通道处于暂停状态，
Homebrew 自 2026-09 起也不再上架未通过 Gatekeeper 检查的软件。

## 设计说明

- 系统字体栈（SF Pro / 苹方 / 雅黑），自动跟随系统深浅色。
- Windows 使用 `titleBarOverlay`、macOS 使用 `hiddenInset`，自绘极简顶栏（可拖拽）。
- 同一个 Markdown 同一时刻只允许在一个窗口里打开（主进程里一张「文档归属表」，`doc:claim` / `doc:release` / `doc:owner` 三个通道）：被占着时打开请求不会成功，只把持有它的窗口切到前面。归属随窗口走 —— 窗口切换文档就把上一篇让出去，窗口关闭、关闭工作空间、文档被删除时自动释放，所以关掉窗口后别的窗口立刻能接手（不是文件锁，进程退出后不留痕）。
- **侧栏两页互斥，状态是单枚举**：`sidePane: 'files' | 'outline'`（键 `jianmo.sidebarPane`），`setSidePane()` 是**唯一**改 `body.side-outline` 的地方，CSS 那边就是 `body.side-outline #outline { display: block }` / `#tree { display: none }`。⚠️ 早先是两个独立布尔（`tocOpen` 管右侧目录、`no-sidebar` 管侧栏），能组合出「文件树和大纲同时开着」这种非法态；**单枚举从根上不存在这种可能**，别再退回两个开关。`Esc` 也不收它 —— 它是栏里的一页不是浮层。
- **「文档目录」按钮已经删掉了**：目录并进侧栏之后，右侧那排图标最左边原本是它，现在换成了「打开文件夹」（`#btn-open-folder-ws`，与欢迎页那个按钮同一个 `chooseFolder` 入口）。⚠️ 它曾经过两轮搬迁：`position: absolute` 挂在 `#content` 上、落在正文右侧留白里（横向位置靠 `--toc-btn-right` 从留白宽度反推），后来搬进顶栏 `.topbar-right`。那套算式连同 `--toc-btn-w` / `--toc-btn-right` 早已删除，**别再复活**。`Ctrl/Cmd + Shift + O` 的语义也随之从「开合面板」变成「切页」，菜单项文案是「显示 → 切换到文档大纲」。
- **正文占满，留白恒定最小**：`#editor` 只有 `width: 100%; padding: 40px var(--content-pad) 48px` —— **没有 `max-width`、没有 `margin: 0 auto`**。曾实现过定宽中轴（38em / 76ch+ 居中）并在 README 里论证过「中文行宽 30–40 字」，但**已撤销**：中轴必然在两侧各留一大片空白（1080 宽各约 250px、1600 宽各约 500px），那片空白既不是内容也不是控件位置，纯空着却比「字排得宽」更抢眼。⚠️ `#editor` 与 `#source-editor` 的 `padding` 必须逐值相同（都是 `40px var(--content-pad) 48px`），否则切换模式时第一行会跳。⚠️ 滚动条槽（`scrollbar-gutter: stable`）在 `padding` **之外**，所以左右天然对称、`--sb-w` 已删除 —— 别再写回 `calc(var(--content-pad) - var(--sb-w))` 那个「扣滚动条凑对称」的算法。
- **⚠️ `var()` 在自定义属性里的代入时机**：`--x: calc(var(--content-pad) / 2)` 若写在 `:root` 里，代入的是 **`:root` 自己的** `--content-pad`，而 `--content-pad` 一旦被挪到 `body` 上按档位覆盖（早先的窄 / 中 / 宽三档就是这么干的），这里代进去的还是 `:root` 的那个值 —— 三档按钮会齐齐停在同一个位置（实测踩过，还是靠**三档各量一次**才发现的）。结论：这类「由别的变量推出来的变量」必须和它依赖的变量**声明在同一个元素**上，或者干脆把 `calc()` 写在使用处。现在留白固定了、不存在分档覆盖，但这条约束仍然写在这里，因为它是加档位时最容易踩的坑（当年的实例就是 `--toc-btn-right`，已随按钮搬进标题栏一起删掉）。
- **面板只往编辑区里摊，窗口一动不动**：侧栏的布局宽度（264 → 0）是页内重排。`ui:resize` 只管欢迎页 480 / 工作区 1000 这两套基准尺寸，与面板无关 —— 所以「主进程按增量挪窗口」那套机械（`window:pad` / `applyWindowPanels` / 最大化后补账）已经整段删掉了。
  - **工作区宽度为什么是 1000**：它是「侧栏 264 + 编辑区 + 滚动条」一起住的那个宽度，按用户要求收窄到 1000（历史：1020 → 1180 → 1200 → 1000）。侧栏全开时正文可用 = `1000 − 264 − 滚动条 10 − 左右内边距 40` = **696px**。
  - **窗口最小宽度分两套**：工作区 `600`、欢迎页 `460`（欢迎页本身只有 480 宽，拿 600 卡它连创建都别扭）。`ui:resize` 里**先松最小宽度、再换尺寸** —— 顺序反了的话，从工作区退回欢迎页会被 600 卡住、缩不到 480。
  - **换尺寸后夹回工作区**：两套基准尺寸差 520px 宽，贴右站着的窗口（或在分屏 / 小屏上）一切到工作区就会有一条跑到屏幕外，所以 `ui:resize` 走 `fitToWorkArea()` —— **只挪位置，不改尺寸**；窗口本身比工作区还大的时候贴左上，不去缩它。
  - **为什么不再改窗口尺寸**：窗口几何只能**瞬时**变（`setBounds` 没有动画可放），而侧栏宽度是带动画的 —— 一改窗口两者必然错帧：收起时窗口先跳到窄尺寸、侧栏还要 180ms 才缩完，正文被挤窄再弹回。要真正对齐只能 rAF 逐帧同时改侧栏宽和 `setBounds`，但两边的时间线由不同进程驱动、必然差一两帧，那点残差会变成正文的横向抖动。窗口不动就完全没有这一类问题，动画反而能放回来：`#sidebar { transition: width }`（只有拖拽调宽时才用 `body.resizing` 关掉）。
  - **`PANELS_EXCLUSIVE_W`(800) 与 `TOC_PAD`(246) 已删除**：目录不再是右侧那块独立面板，它不与侧栏抢空间，压根不存在「两块谁让谁」的问题。同批删掉的还有 `panelsExclusive()`、`body.toc-open` 给编辑区加的 `margin-right: 246px`、以及 `#editor-wrap { transition: margin-right }`（没有让位就没有过渡可做）。⚠️ 见到 `246` / `800` 这两个数先确认上下文 —— 它们曾经是面板几何的两根支柱，现在只在历史记录里有效。
  - **`EDITOR_MIN = 480` 只干一件事：给侧栏宽度定上限**（`sidebarMaxWidth`，拖拽与夹窄共用；口径是「正文能用到的宽度」，所以算账要扣掉滚动条）。
  - **侧栏宽度只有一个出口 `applySidebarWidth()`**：渲染宽度 = 偏好宽度（`sidebarPref`）∩ 此刻上限，收着的时候也照算。⚠️ 夹窄**不写 localStorage** —— 早先的写法把夹取值写回 DOM 并持久化，于是在窄窗口里开一次目录侧栏就被永久记住那个窄值（900 宽下夹到 180，窗口拉回来还是 180）；现在空间一回来就自动还给你，节点上那句「偏好的归偏好、渲染的归渲染」也是同一条。
  - 验证方式：`build/_verify_pane.cjs`（28 条）覆盖两页互斥、切页不改窗口/正文尺寸、状态栏三段同基线、四种形态；逐帧采宽度的旧脚本 `_verify_panels.cjs` 里与 `246 / 800` 相关的断言已随之重写。
  - **文件树懒加载**：`listTree` 在主进程里是**单层**扫描（不递归），目录节点不带 `children`；渲染层展开时才经 `fs:children` 读那一层，读到的结果**挂回数据树里那个节点**。⚠️ 必须挂数据树里的节点、不能只挂传进来的那个对象 —— 读盘期间 `fs:changed` 可能触发 `setData` 换掉整棵树，对象全换了（踩过：日志显示读完、render 也调了，DOM 却始终停在「载入中」，只有折叠再展开才恢复）。⚠️ `setData` 还要把旧树里已加载的 `children` **按路径搬到新树**，否则自动保存触发的每次刷新都会让用户展开的目录集体退回「载入中」。
- 删除操作移入系统废纸篓（可恢复），不做不可逆删除。
